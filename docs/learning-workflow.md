# AIと壁打ちしながら育てる

一度に一つの問いを選び、対話で考え、根拠を確かめ、その結果を既存のノートへ戻します。次回は残った問いから再開します。[次に考える問い](../learning/README.md)が入口です。

## 三つの役割を分ける

**過去の記録**は、各分野のsources/と「当時の本文」を含む移植ノートです。原文・来歴・初期移植時のAI補足を読み返す場所として扱います。内容上の誤りを見つけても、当時の本文を現在の説明に書き換えません。

**育てるノート**は、一つの問いについて現在の説明、根拠、具体例、残った問いをまとめる場所です。今ある[基底変換](../math/linear-maps-and-matrices.md)、[保存則と構成式](../physics/conservation-and-constitutive-laws.md)、[平衡と速度](../chemistry/reaction-direction-and-rate.md)がその入口です。同じ問いの説明はここに集め、原文の該当行へリンクします。新しい問いとして独立する場合に限り、新しいノートを作ります。

**次に考える問い**は、未解決の内容と再開場所を短く案内する一覧です。詳細や結論はノート側に置き、一覧へ重複して書きません。関心が変われば候補を入れ替え、一区切りついた問いは一覧から外しても、理由や残った課題はノートに残します。

今あるURLを保ちながら、この役割分担で育てます。現時点では、全ファイルの移動や分類の作り直しは必要ありません。移植ノートの判別にはfrontmatterのprovenanceと「当時の本文」の見出しを使えます。

## 1回の壁打ち

1. **問いを選ぶ。** 対象ノートと原文の該当箇所を読む。AIには、関連する既存ノートを先に探してもらう。本人がいまどう理解しているかは、本人の言葉から確認する。
2. **小さく考える。** 前提をそろえ、一つの具体例・導出・反例を扱う。広がった話題は残った問いへ置き、全部を一度に解こうとしない。
3. **確かめる。** 出典の該当節や計算と照合する。未確認の説明はその旨を残し、AIの説明が自然に読めることだけで確認済みにしない。
4. **ノートへ戻す。** 現在の説明を更新し、訂正なら理由を残す。本人の発言とAIの補足を区別し、関連リンク・updatedの日付・問いの一覧も必要に応じて更新する。
5. **次の一歩を残す。** 「次は何を調べる／計算するか」を一つ書く。時間がなければ、結論を急がず、そこまで考えたことと未解決の点だけを残す。

対話の全文を毎回公開する必要はありません。公開するのは、その問いを再開するのに役立つ説明と根拠です。私的な対話や生のログを保存したい場合は、Git管理外のinbox/へ置きます。

## そのまま使える依頼例

~~~text
learning/README.mdと関連する既存ノートを読んで、
「基底の選び方で数値計算の誤差はどう変わるか」を一緒に考えたい。

まず今ある説明と未解決の点を短く整理して、
私の理解を確認しながら、一つの具体例で壁打ちして。
定義・仮定・直感を分け、根拠や計算で確かめてほしい。

一区切りしたら、今の説明、確認した根拠、残った問い、
次回の一歩を既存ノートへ反映して。
当時の本文は保存し、私が発言していない感想や理解は補作しないで。
~~~

途中で再開するときは、「このノートの残った問いから再開したい。前回から変わった点も確認して」で始められます。原文や以前の対話が見つからない場合、AIは文脈を推測で埋めず、わかる範囲を示します。

## 理解の変化を残す

実質的な訂正や見方の変化があった場合にだけ、ノート末尾へ短い記録を添えます。体裁の修正はGitの差分に任せ、毎回日記を増やす必要はありません。

- 日付と、どの問いを扱ったか。
- 以前の説明から何を変え、どの根拠で変えたか。
- 本人の発言として残す内容があれば、その言葉や確認できた要旨。
- まだ確かめていない点と、次に行う確認。

書き方は[ノートのひな形](../templates/note.md)を参照してください。本人が「理解できた」と言っていないのに、理解の到達点として記録しません。status: reviewedも、人が内容と出典を確認した指示がある場合だけ使います。

## 再生成と日常の更新を分ける

取り込みスクリプトは、2026-09-20時点のスナップショットを変換する道具です。日々のノートを更新するたびに再実行するものではありません。新しい説明は育てるノートのMarkdownを直接編集します。Python内の初期補足を日常の執筆場所にはしません。

移植ノートへ訂正や関連ノートのリンクを手で追加する場合は、「当時の本文」の外側へ記し、初期のAI補足と日付を分けます。検証の--checkは実行できます。再生成は手編集を検出すると停止するため、--overwriteで押し切らず、必要な変更を個別に取り込んでください。新しいScrapboxの版を取り込む場合も、元のスナップショットの置き換えとは別に扱います。

検証器は原文・本文の整合性とリンクなどを確認するもので、追記の内容や数理的正しさの保証ではありません。実行方法は[取り込みガイド](importing.md)にあります。
